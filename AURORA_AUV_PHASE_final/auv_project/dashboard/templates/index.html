Sensor fault injection

Editable while the simulation is running: a change here is sent to the running robot and applied at once (no stop, no restart). The sensor model really changes its output, and the panels/charts follow it: healthy normal output · degraded samples keep coming but much noisier (still used) · failed a real sample every cycle, but its output is stuck at 0.0 and never changes (rejected by the EKF) · discarded no output at all, so its readings stop changing (frozen at the last sample) · link cut no data reaches the computer, same effect reported as a link fault. With every sensor discarded / link cut the sensor system delivers nothing and no sensor value is shown anywhere.

    Controller gains read from the controller that is actually driving

    Read live from whichever controller is producing the commands, nothing computed in the browser. On the legacy Phase-4 mission that is the adaptive P controller: the proportional gain the vehicle is actually using, the gain schedule (which rises near the target) and the self-tuning term (which ramps up while stalled and relaxes while tracking well), each capped by simulation.controller.adaptive.gain_boost, plus the heading loop's gain (full when aligned, floored for large heading errors). With autonomous navigation on the Phase-5 path follower drives instead, and this panel shows its gains in the units they are applied in (velocity, heading and depth loops) together with the speed schedule that shapes the command. Gain tracking below is that controller's own cumulative record: which way it pushed on the last step and why, how much simulated time it spent in each mode, and the tracked peak / mean / slowest values.
