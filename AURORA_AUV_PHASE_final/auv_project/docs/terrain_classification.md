# Terrain Classification — Week 3

This document covers the Week 3 deliverable: turning the Week 2 processed
bathymetry grid into a per-cell terrain classification (`Flat/Sand`,
`Rocky`, `Steep/Terrain Hazard`, `Obstacle`) using engineered features and a
Random Forest classifier.

## 1. Pipeline Overview

```text
processed_bathymetry.npy (100x100, positive_down)
          |
          v
  feature_extraction.py  ->  depth, slope, roughness, curvature grids
          |
          v
  label_generation.py    ->  synthetic class labels (rule-based, thresholds in config.yaml)
          |
          v
  classifier.py           -> stratified train/val/test split -> RandomForestClassifier
          |
          v
  evaluate.py              -> accuracy, macro-F1, confusion matrix, feature importances
```

Entry point: `python -m src.terrain.run_pipeline`

## 2. Feature Extraction (`src/terrain/feature_extraction.py`)

Four features are computed per cell, all resolution-aware (scaled by
`environment.resolution` metres/cell so results don't depend on grid spacing):

| Feature   | Definition | Units |
|-----------|-----------|-------|
| `depth`     | raw depth value (positive_down) | m |
| `slope`     | gradient magnitude `sqrt((dz/dx)^2 + (dz/dy)^2)`, central differences | rise/run (dimensionless) |
| `roughness` | local standard deviation of depth in a `roughness_window` x `roughness_window` neighbourhood | m |
| `curvature` | discrete Laplacian `d^2z/dx^2 + d^2z/dy^2` | 1/m |

Measured on the real Week 2 grid (`resolution=1.0`, `roughness_window=3`):

| Feature   | min | max | mean |
|-----------|-----|-----|------|
| slope     | 0.0095 | 7.98 | 1.82 |
| roughness | 0.34 | 4.47 | 1.72 |
| curvature | -6.34 | 8.57 | 0.02 |

## 3. Threshold Recalibration (documented, not silent)

`configs/config.yaml` already shipped a `terrain.synthetic_label_thresholds`
block before this feature code existed:

```yaml
slope_rocky: 0.15
slope_steep: 0.35
roughness_obstacle: 2.5
```

These were placeholder values with no grounding in the actual feature
scale. Applied to the real grid, they classify **96.7%** of all cells as
`Steep/Terrain Hazard` or `Obstacle` — a degenerate distribution that would
make the classifier trivially predict the majority class and provide no
useful navigability signal.

The Week 3 task spec explicitly calls for investigating this and making the
thresholds configurable and documented rather than silently forcing a
result, so the *values* (not the keys or semantics) were recalibrated
against a percentile search over the real slope/roughness distributions:

```yaml
slope_rocky: 1.65
slope_steep: 2.35
roughness_obstacle: 2.8
```

Resulting distribution on the real 100x100 grid (10,000 cells):

| Class | Name | Count | Fraction |
|-------|------|-------|----------|
| 0 | Flat/Sand | 4918 | 49.2% |
| 1 | Rocky | 2341 | 23.4% |
| 2 | Steep/Terrain Hazard | 2283 | 22.8% |
| 3 | Obstacle | 458 | 4.6% |

This is a reasonable, non-degenerate split: no class is empty, no class
dominates past ~50%, and the minority `Obstacle` class (a physically rare
category — very rough terrain — expected to be uncommon) still has enough
examples (458 cells) to stratify across train/val/test and be learned.

**Label rule** (`label_generation.generate_labels`), roughness checked
first so a locally very irregular cell is always `Obstacle` regardless of
its net slope:

```text
roughness > roughness_obstacle        -> 3 (Obstacle)
elif slope > slope_steep              -> 2 (Steep/Terrain Hazard)
elif slope > slope_rocky              -> 1 (Rocky)
else                                   -> 0 (Flat/Sand)
```

## 4. Classifier (`src/terrain/classifier.py`)

- **Model:** `sklearn.ensemble.RandomForestClassifier` (`n_estimators=200`,
  `max_depth=None`, `class_weight="balanced"` to compensate for the
  minority `Obstacle` class, `random_state=42` for reproducibility).
- **Split:** stratified 70/15/15 train/val/test (config: `train_split`,
  `val_split`, `test_split`), stratification ensures `Obstacle` (4.6% of
  cells) is present in every split.
- **Persistence:** `joblib` dump/load to `models/terrain_classifier.pkl`.

## 5. Evaluation & An Honest Caveat

Test-set results (1,500 held-out cells):

| Metric | Value |
|--------|-------|
| Accuracy | 0.9993 |
| Macro F1 | 0.9978 |
| Weighted F1 | 0.9993 |

Feature importances: `slope` 0.627, `roughness` 0.365, `depth` 0.006,
`curvature` 0.003.

**This near-perfect score is expected, not a sign the model is unusually
good.** The labels are generated by a deterministic threshold rule applied
directly to `slope` and `roughness` — the same two features the classifier
is trained on. A Random Forest can essentially re-derive that threshold
rule from the data, which is exactly what the feature-importance split
(slope + roughness ≈ 99% of importance, depth/curvature ≈ negligible)
shows it has done. This evaluation demonstrates the pipeline (feature
extraction -> labels -> split -> train -> evaluate) is wired correctly end
to end, **not** that the model has learned any real-world seafloor
navigability judgment — there is no real labeled survey data in this
project to learn that from. See `docs/dataset.md` and
`docs/architecture.md` (Stage 4 note) for the same disclosure.
